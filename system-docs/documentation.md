3. Requirements Before Development
Do not begin implementation immediately.
First:
1. Define the problem.
2. Identify stakeholders/users.
3. Gather and analyse requirements.
4. Define functional and non-functional requirements.
5. Prioritise requirements.
6. Estimate software effort.
7. Define the scope of the system to be completed within the 48-hour period.
Your requirements and effort estimation should guide your implementation decisions.
4. Software Effort Estimation
Select and apply an appropriate effort-estimation technique, such as:
• Function Point Analysis
• UseCasePoints
• COCOMO/COCOMOII
• Story points
• Expert estimation
• Another justified estimation approach
Explain:
• Whythetechnique was selected
• Estimated effort
• Estimated person-hours
• Estimated development duration
• Assumptions
• Constraints
• Howtheestimation influenced your project scope

5. System Design
Develop appropriate design artefacts before or alongside implementation.
Depending on your project, these may include:
• Systemarchitecture
• Use-case diagram
• Class diagram
• Sequence diagram
• Activity diagram
• ER/database diagram
• Component diagram
• UIwireframes
• Data-flow diagram
You do not need to produce every possible diagram. Select the diagrams that best
communicate your system.
6. Implementation
Develop a functional software application, not merely:
• Aproposal
• Arequirements document
• AUImock-up
• Astatic website
• Anon-functional prototype
The application should implement the major prioritised requirements.
Where applicable, include:
• Front-end
• Back-end
• Database
• Authentication
• Authorisation
• APIintegration
• Input validation
• Error handling
• Security controls
• Responsive interface
7. Technical Debt
You must explicitly consider technical debt during the project.
Document technical debt introduced because of:
• 48-hour time constraints
• Design shortcuts
• Simplified architecture
• Incomplete refactoring
• Temporary solutions
• Limited testing

• Codeduplication
• Dependency choices
• Security compromises
• Incomplete documentation
For each significant technical debt item, identify:
Debt → Cause → Impact → Priority → Proposed Resolution
You should clearly distinguish between technical debt that is:
• Acceptable temporarily
• Scheduled for future resolution
• Critical and requiring immediate attention
8. Testing
Develop and execute appropriate tests.
At minimum, provide evidence of relevant:
• Functional testing
• Unittesting, where applicable
• Integration testing, where applicable
• Systemtesting
• Useracceptance testing
Where appropriate, also consider:
• Security testing
• Usability testing
• Performance testing
Document:
• Testcase
• Expected result
• Actual result
• Pass/fail
• Defects identified
• Corrective action
